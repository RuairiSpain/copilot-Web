## requiredVersions verification

21 azd ranges and 24 extension constraints were run through `doctor --rules FND-CFG-001` and compared with the real libraries. The grammar in `docs/spikes/azd-required-versions.md` matches the library on every documented form. Invalid for azd (error finding): comma form, `~1.2.0`, `^1.0.0`, `1.X`, `latest`, `*`, `=>1.0.0`, leading or trailing `||`, empty string, numeric YAML value. A known azd version outside the range gives `required-versions-azd-out-of-range`; an unknown version gives an `azd-version-unknown` skip. Extensions: validity matches the library except `latest` and the empty string, which azd special-cases (`manager.go` `matchesVersionConstraint`) and the tool correctly accepts; an invalid constraint is an uncertain note, never an error. The catalogue claims in tool-compatibility.md section 6 match the rules (37 rules `>=1.34.2 <=1.36.0`, ENV-001..004 `<=1.36.0-beta.1`, SEC-007/011/014 `>=1.36.0-beta.1 <=1.36.0`); `schemas/v1.0/azure.yaml.json` is byte-identical at azure-dev-cli_1.35.0, 1.36.0 and main.

## Unsupported assumptions still in the code

Whether azd warns about ignored extra YAML documents; that azd's `.env` parser is godotenv v1.5.1, mirrored by `project.ParseDotEnv`; that azd exports `AZURE_ENV_NAME` to extensions (ADR-004 section 4); that `.azure/config.json` `defaultEnvironment` is azd's default selection; name-only secret heuristics and the `sk-` shape. The semver libraries were executed by the reviewer (the spike note says "read, not executed"); the spike's other unverified claims (exit code 1, older azd releases, non-interactive extension auto-install) were not checked.
