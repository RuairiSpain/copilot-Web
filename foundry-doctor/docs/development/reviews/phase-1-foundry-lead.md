# Phase 1 review: Foundry lead

> **Scope note (2026-10-15).** This review examined the implementation archived on branch `claude/foundry-doctor-phase-1-core-archive`
> (commit `2b1c135`), which was replaced on this branch by the implementation already merged to `main` (PR #18). The findings below name
> files of the archived code. They are kept as an independent checklist: re-check each one against `main`'s rules before relying on it.


Reviewer: `foundry-lead` (independent; did not write the code). Date: 2026-10-12. Verdict on the first submission: **REJECT**.
Scope: azure.yaml handling, project and environment discovery, `.env` handling, synthetic infrastructure, and the CFG, ENV, COST-002 and OPS-007 rules.

Unmet DoD items on the first submission: "all rule facts verified" (B1), "skipped never passed / fail safely on unknown versions" (B3), "rules must not false-pass or false-fail" (B2).

| id | severity | where | finding | fix proposed by the reviewer |

| B1 | blocker | `internal/rules/ops/ops007.go` | Pipeline files are looked up under the azure.yaml directory, not the git repository root. azd resolves them from the repo root (`pipeline_manager.go` `GetRepoRoot`, falls back to the project dir; `hasPipelineFile(provider, repoRoot)`). A project in a subfolder gets a false `no-pipeline` fail. | Walk up from the project root to the directory holding `.git` and look there. No `.git`: fall back to the project dir and mark the finding uncertain. Test for a nested azure.yaml. |
| B2 | blocker | `ops007.go` `pipelineSection` | An azure.yaml `pipeline:` section (provider, variables, secrets) only holds inputs to `azd pipeline config`; it does not show a pipeline exists. The rule passes on it. | Treat it as at most uncertain or ignore it. Pass only when a file is found. Fix the catalogue evidence text. |
| B3 | blocker | `internal/project/azd.go` `Versions`; `internal/rules/executor.go` `versionGate`; `internal/rules/cfg/cfg001.go` | Version handling is a no-op. Installed azd and extension versions are never detected; an undetected version counts as in range unless strict. azure.yaml `requiredVersions.azd` and `requiredVersions.extensions` are never compared with the verified ranges. ADR-004 section 5 says a declared or installed version outside range makes the rule skipped with `unsupported-version`, and an unsatisfied `requiredVersions.azd` is an error finding. Nothing emits `unsupported-host` either. | Use declared `requiredVersions` as the version evidence when nothing is detected. Skip with `unsupported-version` when the declared range is not inside the verified range. Error finding for an unsatisfied `requiredVersions.azd` only when the azd version is known. Say "versions not detected" in the report header. Surface unknown host as an info finding. |

Reviewer-confirmed correct: vendored schemas match azure-dev main apart from the documented `$id`/`$ref` rewrite; `.env` grammar matches godotenv v1.5.1; `defaultEnvironment` handling; ENV-001 precedence note; CFG-004 bounds, CFG-011 minimums, ignored hosted-agent fields and the reserved prefixes; CFG-003 `uses` requirements; skip semantics in CFG-004/005/012; COST-002 key behaviour; hostile azure.yaml ends in an error or under 3 s with no panic or hang; all 15 in-scope catalogue entries have `sources` with `verifiedVia` and `lastVerified`.

Assumptions with no verified source (reviewer list): ARM rejecting display-name locations; secret-looking env var names; `AZURE_TENANT_ID` not being a standard azd variable; multi-document azure.yaml being an azd error; empty `infra.provider` implying synthetic infrastructure; the CFG-007 "internal Container Apps ingress" recommendation; a `pipeline:` section implying a pipeline exists; whether `AZURE_ENV_NAME` or `AZD_ENVIRONMENT` override the default environment.

Missing tests named by the reviewer: OPS-007 nested azure.yaml and `pipeline:`-only; version gating above/below the verified range and strict with undetected versions; CFG-005 names and `${VAR:-literal}`; CFG-012 `Global` and display names; ENV-002 identical `AZURE_ENV_NAME`; ENV-001 with no group/subscription; ENV-001..004 with one unreadable/over-cap sibling; CFG-006 standard variables; multi-document azure.yaml.

Limits of the review: ENV-rule behaviour could not be run through the CLI (a repo guard blocks shell writes of `.env`); the reviewer relied on code reading and the unit tests for those rules.
