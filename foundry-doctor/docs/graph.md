# Graph outputs

`foundry-doctor graph` renders the Phase 1-3 correlation graph without changing
validation semantics.

## Formats

- `mermaid`: primary portable text output
- `json`: machine-readable graph matching `schemas/graph.schema.json`
- `markdown`: summary plus embedded Mermaid
- `dot`: Graphviz/DOT text
- `html`: self-contained HTML wrapper around the Markdown summary

Mermaid output is intentionally restricted to a stable `flowchart LR` subset:

- opaque node IDs generated by Foundry Doctor
- quoted labels only
- escaped quotes, backslashes and newlines
- class-based styling rather than inline executable content

## Modes

- `--source`: local `azure.yaml` plus optional compiled ARM/Bicep
- `--deployed`: read-only Azure inventory projection
- `--combined`: merged source and Azure view, highlighting drift through node
  origins (`local`, `azure`, `both`)

Source mode works without Azure login. Deployed and combined modes require a
subscription ID and use read-only Azure inventory APIs. When `--account` and
`--project` are supplied, runtime overlays use project-scoped Foundry hosts and
connections plus account-scoped deployments. `--account` also requires
`--resource-group`; `--project` requires both `--account` and
`--resource-group`.

If the Azure inventory listing would be truncated, the command exits
unavailable instead of emitting a partial deployed/combined graph.

## Legend

| Origin | Meaning |
|---|---|
| `local` | Present only in local source inputs |
| `azure` | Present only in deployed Azure state |
| `both` | Correlated between source and Azure |
| `external` | Referenced outside the current project scope |
| `missing` | Referenced locally but unresolved |

Common node kinds include `project`, `agent`, `model`, `connection`,
`toolbox`, `identity`, `role`, `network`, `search`, `storage`, `apim`,
`monitoring`, and generic `resource`.

Collapsed summary buckets keep their underlying origin (`local`, `azure`,
`both`, `external`, or `missing`) and are additionally marked with
`collapsed: true`.

## Accessibility

- `markdown` and `html` always include the exact Mermaid source as text for
  review tools and screen readers.
- Labels remain plain text after escaping; no hidden rendered-only metadata is
  required to understand the graph.
- Large graphs can be collapsed with `--collapse-after`, `--max-nodes`, and
  `--max-edges` so review diffs stay readable.

## Overlays

`--findings-report <report.json>` overlays existing Foundry Doctor JSON report
findings on matching nodes. Active findings mark nodes unhealthy; baselined
findings are counted separately and remain visible.

Connection/runtime error summaries are sanitized before rendering, and
`--redact-ids` deterministically obfuscates friendly names while removing
resource IDs, source locations, and health text from node payloads.

When runtime connection metadata includes a backing Azure `ResourceId`, graph
output adds a `targets` edge from the Foundry connection to the correlated
Azure resource node. Source mode also emits deterministic `targets` edges from
local `azure.ai.connection` services when `target` is declared in `azure.yaml`.

## Examples

```text
foundry-doctor graph --source --format mermaid
foundry-doctor graph --combined --subscription <sub> --resource-group <rg> --account <acct> --format markdown --out graph.md
foundry-doctor graph --source --findings-report foundry.json --redact-ids --format json
```
